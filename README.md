# แจ้งน้ำท่วม นนทบุรี: คู่มือติดตั้ง (รุ่นมีหน้าแอดมินและแผนที่จริง)

หน้าเว็บอยู่บน GitHub Pages ฐานข้อมูลและระบบล็อกอินอยู่บน Supabase (แผนฟรี)

## ไฟล์ในชุดนี้
| ไฟล์ | ใช้ที่ไหน | ทำอะไร |
|---|---|---|
| `index.html` | อัปโหลดขึ้น GitHub | หน้าประชาชน: ภาพรวม (แผนที่จริง) และแจ้งเหตุ |
| `admin.html` | อัปโหลดขึ้น GitHub | หน้าเจ้าหน้าที่: ล็อกอิน จัดการรายงาน ระดับตำบล ผู้ดูแลระบบ |
| `config.js` | อัปโหลดขึ้น GitHub (ต้องแก้) | ใส่ URL และคีย์ของ Supabase (ใช้ร่วมกันทั้งสองหน้า) |
| `.github/workflows/pages.yml` | อัปโหลดขึ้น GitHub | สั่งให้ GitHub เผยแพร่หน้าเว็บ (ต้องใช้ไฟล์ใหม่ เพราะต้องคัดลอก `admin.html` ด้วย) |
| `supabase/schema.sql` | วางใน SQL Editor | สร้างและอัปเกรดฐานข้อมูล รันซ้ำได้ ข้อมูลเดิมไม่หาย |
| `supabase/first_admin.sql` | วางใน SQL Editor | ตั้งแอดมินคนแรก (super) |
| `supabase/reset.sql` | ใช้เมื่อต้องการล้างทิ้งเริ่มใหม่ | ลบตารางเดิม **รวมข้อมูลทั้งหมด** |

## ถ้าติดตั้งรุ่นก่อนหน้าไว้แล้ว (อัปเกรด)
1. ใน Supabase เปิด SQL Editor วางเนื้อหา `supabase/schema.sql` ใหม่ทั้งไฟล์ แล้วกด Run (ข้อมูลรายงานเดิมยังอยู่ รายงานเก่าจะใช้เวลารับแจ้งเป็นเวลาเกิดเหตุ)
2. แทนที่ `index.html`, `.github/workflows/pages.yml` และเพิ่ม `admin.html` ใน repo (ไม่ต้องแตะ `config.js`)
3. ทำขั้นที่ 3 ด้านล่างเพื่อตั้งแอดมินคนแรก แล้วรอ Actions เป็นสีเขียว กด Ctrl+F5

## ติดตั้งใหม่ตั้งแต่ต้น
### ขั้นที่ 1 สร้างฐานข้อมูล
1. สร้างโปรเจกต์ที่ supabase.com
2. SQL Editor วาง `supabase/schema.sql` ทั้งไฟล์ แล้ว Run
3. ผลท้ายสุดมี 14 แถว แถวที่ 1–13 ต้องเป็น `true` ส่วนแถวที่ 14 (มีแอดมิน super) จะเป็น `false` จนกว่าจะทำขั้นที่ 3 ถ้าแถว 1–13 มี `false` หรือมีข้อความสีแดง ให้หยุดและส่งภาพมาดู

### ขั้นที่ 2 ใส่ค่าเชื่อมต่อใน config.js
คัดลอก **Project URL** (`https://xxxx.supabase.co` ไม่มี `/rest/v1/`) และ **Publishable/anon key** จาก Project Settings → API ใส่ใน `config.js` ห้ามใช้ `secret` หรือ `service_role`

```js
window.FLOOD_CONFIG = {
  supabaseUrl: "https://xxxxxxxx.supabase.co",
  supabaseAnonKey: "sb_publishable_xxxxxxxx"
};
```

### ขั้นที่ 3 ตั้งแอดมินคนแรก
1. Supabase → **Authentication → Users → Add user → Create new user** ใส่อีเมลและรหัสผ่านของคุณ ติ๊ก **Auto Confirm User**
2. เปิด `supabase/first_admin.sql` แก้อีเมลให้ตรง แล้ววางใน SQL Editor กด Run ต้องขึ้น 1 แถว
3. เปิด `https://ชื่อบัญชี.github.io/ชื่อ-repo/admin.html` ล็อกอินด้วยอีเมลและรหัสผ่านนั้น

### ขั้นที่ 4 ขึ้น GitHub
อัปโหลด `index.html`, `admin.html`, `config.js` (ที่แก้แล้ว), `.github/workflows/pages.yml`, โฟลเดอร์ `supabase/` เข้าสาขา `main` แล้วตั้ง **Settings → Pages → Source = GitHub Actions** รอแท็บ Actions เป็นเครื่องหมายถูกสีเขียว

## เพิ่มแอดมินคนอื่น
- วิธีที่ 1 (ในหน้าเว็บ): ให้คนนั้นกด "ยังไม่มีบัญชี? ขอสิทธิ์เป็นเจ้าหน้าที่" ที่หน้า `admin.html` แล้วสมัครอีเมลและรหัสผ่าน จากนั้นแอดมิน super เปิดแท็บ **ผู้ดูแลระบบ → รออนุมัติ** แล้วกดอนุมัติเป็น admin หรือ super ผู้สมัครที่ยังไม่ได้รับอนุมัติเข้าข้อมูลไม่ได้เลย
- วิธีที่ 2: สร้างผู้ใช้ใน Supabase Authentication เอง (Auto Confirm) แล้วอนุมัติในแท็บเดียวกัน ถ้าไม่อยากให้ใครสมัครได้ ให้ปิด **Authentication → Sign In / Providers → Allow new users to sign up**
- บทบาท `admin` จัดการรายงานและระดับตำบลได้ ส่วน `super` จัดการแอดมินคนอื่นได้ด้วย ระบบบังคับให้เหลือ super ที่ใช้งานอยู่อย่างน้อย 1 คน
- ลืมรหัสผ่าน: Supabase → Authentication → Users แล้วตั้งรหัสใหม่ หรือเปลี่ยนเองในแท็บ "บัญชีของฉัน"

## สิ่งที่ทำได้ในหน้าแอดมิน
- **รายงาน**: เพิ่ม แก้ไข ลบ กรองตามตำบล กรองตามระดับน้ำหรือสถานะน้ำลด กรองช่วงเวลา ค้นหาซอย/ชื่อ/เบอร์ และส่งออก CSV (มีชื่อและเบอร์ผู้แจ้ง เก็บไฟล์อย่างระมัดระวัง)
- **ระดับตำบล**: กำหนดปกติ / เฝ้าระวัง / เตือนภัย / วิกฤต / วิกฤตมาก พร้อมหมายเหตุ แสดงเป็นสีและตัวอักษรบนแผนที่ของประชาชนทันที ถ้าเลือก "อัตโนมัติ" ระบบประเมินจากสถานะถนนที่แย่ที่สุดในตำบล
- **ผู้ดูแลระบบ** (เฉพาะ super): อนุมัติ ปิดใช้งาน เปลี่ยนบทบาท ลบสิทธิ์

## สิ่งที่ประชาชนเห็น
- **ภาพรวม**: แผนที่ OpenStreetMap, ตำบลถูกระบายสีตามระดับ, อันดับตำบลที่มีรายงานมากสุด (กดได้ จะซูมและแสดงรายละเอียดตำบล), เส้นถนนที่น้ำท่วมสีตามสถานะการสัญจร
- **แจ้งเหตุ**: ปุ่มความสูงของน้ำมีรูปประกอบ 8 ระดับ (6–10, 11–20, 21–35, 36–50, 51–100, 101–200 ซม., มากกว่า 2 ม., วิกฤต) น้ำลดแห้งสนิท / น้ำสูง < 5 ซม. เลือกวันและเวลาที่พบเหตุ (ย้อนหลังได้ไม่เกิน 7 วัน) ปุ่มบันทึกพิกัดปัจจุบัน (ไม่บังคับ) และป๊อบอัพ "ยืนยันข้อมูลดังกล่าวเป็นข้อมูลจริง" ก่อนส่ง

## ข้อจำกัดที่ต้องรู้ (อ่านก่อนเปิดใช้จริง)
- **เส้นถนนบนแผนที่** ค้นจากชื่อซอย/ถนนที่ผู้แจ้งพิมพ์เทียบกับชื่อใน OpenStreetMap ผ่านบริการ Overpass โดยเบราว์เซอร์ของผู้เข้าชม ถ้าชื่อไม่ตรงหรือไม่มีในแผนที่ จะแสดงเป็นจุดโดยประมาณแทน ถ้าผู้แจ้งกดบันทึกพิกัด จุดจะแม่นยำกว่า ถ้า Overpass ล่มหรือถูกจำกัด เส้นอาจไม่ขึ้นชั่วคราว
- **ตำบล** ระบบมี 5 ตำบลตามเขตเทศบาลนครนนทบุรี: สวนใหญ่ ตลาดขวัญ บางเขน บางกระสอ ท่าทราย ขอบเขตตำบลโหลดจาก OpenStreetMap ถ้าโหลดไม่ได้จะเป็นวงกลมโดยประมาณ จุดกึ่งกลางตำบลยังเป็นค่าประมาณ ต้องให้เจ้าหน้าที่ตรวจ รายงานเก่าที่ใช้ตำบลอื่นยังอยู่ในฐานข้อมูล แต่แก้ไขไม่ได้จนกว่าจะเปลี่ยนตำบลเป็นหนึ่งใน 5 ตำบลนี้ ถ้าต้องการเปลี่ยนรายชื่อตำบล ต้องแก้ใน `schema.sql` ฟังก์ชัน `valid_tambon` และตัวแปร `TAMBONS` ทั้งใน `index.html` และ `admin.html`
- แผนที่พื้นฐานใช้เซิร์ฟเวอร์ไทล์ของ OpenStreetMap ซึ่งมีนโยบายการใช้งานแบบเบา ถ้ามีผู้เข้าชมจำนวนมาก ควรเปลี่ยนไปใช้ผู้ให้บริการไทล์ที่มีสัญญาใช้งาน
- ไม่มีการยืนยันเบอร์ด้วย OTP ใครก็ส่งรายงานเท็จด้วยเบอร์ใดก็ได้ ระบบจำกัดอัตรา (30 ครั้ง/ชม. ต่อเบอร์ 10 ครั้ง/นาที ต่อไอพี) แต่ไม่ใช่การยืนยันตัวตน แอดมินควรตรวจรายงานที่ผิดปกติและลบได้ในหน้าแอดมิน
- ชื่อและเบอร์โทรเป็นข้อมูลส่วนบุคคลตาม PDPA ต้องมีประกาศความเป็นส่วนตัว ผู้รับผิดชอบ และกำหนดระยะเวลาเก็บ ตัวอย่างคำสั่งลบข้อมูลเก่าอยู่ท้ายไฟล์ `schema.sql` พิกัดที่ผู้แจ้งบันทึกจะแสดงบนแผนที่สาธารณะ
- แผนฟรีของ Supabase มีขีดจำกัดและเงื่อนไขพักโปรเจกต์ที่ไม่มีการใช้งาน ตรวจเงื่อนไขล่าสุดและสำรองข้อมูลสม่ำเสมอ
- เกณฑ์สถานะการสัญจร (≤10 ผ่านได้, ≤20 ระวัง, ≤35 รถเล็กผ่านไม่ได้, มากกว่านั้นสัญจรไม่ได้) เป็นค่าประมาณเพื่อการแสดงผล ไม่ใช่ประกาศของหน่วยงาน

## ความปลอดภัยของข้อมูล (สรุป)
- ผู้เข้าเว็บทั่วไป (`anon`) อ่านตารางตรง ๆ ไม่ได้ ส่งรายงานได้ผ่านฟังก์ชัน `submit_report()` ซึ่งตรวจทุกช่อง และอ่านได้เฉพาะ view `public_reports` ที่ไม่มีชื่อและเบอร์
- ชื่อและเบอร์อยู่ในตาราง `reporters` ที่มีแต่แอดมินที่ล็อกอินและได้รับสิทธิ์เท่านั้นอ่านได้ ฟังก์ชันของแอดมินทุกตัวตรวจสิทธิ์ในฐานข้อมูลอีกชั้น ไม่ได้อาศัยหน้าเว็บ
- การสมัครบัญชีไม่ให้สิทธิ์อะไรเลยจนกว่าแอดมิน super จะอนุมัติ
